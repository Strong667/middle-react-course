# Задача 4. Отложенные результаты через useDeferredValue

## Цель

Показать пользователю временное отставание результатов.

## Что нужно сделать

1. В отдельном режиме той же лаборатории замените две поисковые переменные на text и useDeferredValue(text).
2. Показывайте запрос, к которому относится список; при несовпадении значений выводите текст «Обновляем результаты».
3. Объясните отличие от debounce и ограничение для одного длинного синхронного цикла.

## Требования к результату

- В список не передаётся свежий text дополнительным prop, разрушающим границу memo.
- Старые результаты не подписаны как результаты нового запроса.

## Запуск

```bash
cd 01-advanced-react/task4
npm install
npm run dev -- --host 127.0.0.1
```

## Наблюдения

1. Режим deferred

   К лаборатории из задачи 3 добавлен третий режим. В нём остаются только `text` и `deferredText = useDeferredValue(text)`, `listQuery` не обновляется. В `Results` передаётся один prop `query={deferredText}`, свежий `text` туда не попадает, поэтому `memo` не перерисовывает список, пока `deferredText` не поменялся.

2. Подпись к списку

   Над списком написано «Результаты для «…»» с тем же значением, которое получил список. Если `text !== deferredText`, рядом появляется «Обновляем результаты», а список становится полупрозрачным.

   Проверка: быстро ввести «c», стереть, снова «c», потом «s». Пока список не готов, в поле уже «c», а подпись остаётся «Результаты для «»» с пометкой «Обновляем результаты», под ней старые 240 элементов. Промежуточный список для «c» не рисуется вообще. Когда готов список для «cs», подпись и список меняются в одном commit: «Результаты для «cs»», 80 элементов. Старые результаты ни разу не были подписаны новым запросом. По логам `[input]` 1–2 мс на нажатие, `[list] "cs"` через 17 мс после последнего нажатия.

3. Отличие от debounce

   debounce ждёт фиксированную паузу после последнего нажатия и только потом обновляет список, даже на быстром устройстве. Когда таймер срабатывает, рендер списка всё равно обычный и блокирует ввод, пока не закончится. `useDeferredValue` ничего не ждёт: сразу после срочного рендера React начинает фоновый рендер с новым значением, на экране пока старый список, а если пришёл новый символ, React бросает этот рендер и начинает заново. На быстром устройстве отставание почти незаметно, на медленном больше.

4. Ограничение для одного длинного синхронного цикла

   React может прервать рендер только между компонентами. Здесь нагрузка разбита на 240 отдельных `CourseCard`, и между ними React успевает обработать ввод. Если вся работа это один длинный цикл в одном компоненте или функции, остановить его посередине нельзя: пока цикл не закончится, страница не отвечает, и `useDeferredValue` тут не поможет. Такой цикл нужно делить на части или выносить из основного потока, например в Web Worker.

Самопроверка: `npm run build` проходит без ошибок.
