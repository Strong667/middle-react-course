# Задача 6. Управляемый и неуправляемый фильтр

## Цель

Понять владельца значения input.

## Что нужно сделать

1. Сделайте два фильтра: один с value/onChange, второй с defaultValue и чтением значения через ref по кнопке.
2. Добавьте внешнюю кнопку сброса для каждого варианта и явно реализуйте её поведение.
3. Опишите, почему изменение defaultValue после монтажа не является управлением текущим вводом.

## Требования к результату

- В одном input не смешиваются value и defaultValue.
- Сброс и повторный ввод работают в обоих вариантах.

## Запуск

```bash
cd 01-advanced-react/task6
npm install
npm run dev -- --host 127.0.0.1
```

## Наблюдения

1. Управляемый фильтр

   Input с `value={query}` и `onChange`, значением владеет React state. Строка «Состояние: «…»» и список меняются на каждый символ. «Сбросить» вызывает `setQuery('')`, и поле очищается само, потому что оно просто показывает state.

2. Неуправляемый фильтр

   Input только с `defaultValue` и `ref`, значением владеет DOM. React про ввод ничего не знает, пока не нажать «Применить»: тогда значение читается через `inputRef.current.value` и попадает в `applied`, по нему фильтруется список. «Сбросить» сделан явно: `inputRef.current.value = ''`, фокус в поле и `setApplied('')`. Одного сброса state тут мало, поле само не очистится. `value` у этого поля нет, а у управляемого нет `defaultValue`, так что в одном input они не смешиваются.

3. Сброс и повторный ввод

   Управляемый: после «тип» в списке остаётся «Типизация данных», «Сбросить» очищает поле и возвращает все 4 курса, потом ввод «rend» снова фильтрует до «Серверный rendering». Неуправляемый: «Серв» и «Применить» оставляют «Серверный rendering», «Сбросить» очищает поле, ставит в него фокус и показывает «Применено: «»» со всеми курсами, потом «Пров» и «Применить» оставляют «Проверка поведения UI».

4. Почему defaultValue после монтажа не управляет вводом

   `defaultValue` задаёт только начальное значение, по сути HTML-атрибут `value`. После монтажа текущее значение живёт в DOM, и React его при перерисовке не трогает. Кнопка «defaultValue = «React»» меняет state `initial` уже после монтажа. Если в поле что-то введено, например «Серв», там так и остаётся «Серв», меняется только `defaultValue` у элемента. Если поле ещё ни разу не трогали, браузер покажет «React», потому что нетронутое поле берёт значение из атрибута. Но и это не управление: `applied` и список не меняются, а после первого ввода или сброса через ref кнопка на поле больше не влияет. Чтобы поменять текущее значение неуправляемого поля, его нужно записать через ref, как в «Сбросить», или пересоздать input через `key`.

Самопроверка: `npm run build` проходит без ошибок.
