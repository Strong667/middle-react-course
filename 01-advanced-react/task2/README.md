# Задача 2. Действие пользователя — в обработчик, а не в render

## Цель

Перенести действие пользователя из render в обработчик.

## Что нужно сделать

1. Используйте кейс render-side-effect из кейсов, приведённых ниже: запись выбранного id сейчас происходит при вычислении карточки.
2. Сделайте кнопку «Выбрать»: запись в localStorage выполняется только по нажатию; отображение карточки не меняет внешние данные.
3. Объясните, почему перенос записи в Effect без связи с кликом не выполняет требование.

## Требования к результату

- До клика localStorage не меняется; после клика хранится id выбранного курса.
- Повторный render не выполняет новую запись.

## Исходный кейс: render-side-effect

```jsx
function CourseCard({ course }) {
  localStorage.setItem('selected-course', course.id);
  return <h3>{course.title}</h3>;
}
```

Нужное поведение: сохранять id только по нажатию «Выбрать».

## Запуск

```bash
cd 01-advanced-react/task2
npm install
npm run dev -- --host 127.0.0.1
```

## Наблюдения

1. Что не так в исходном кейсе

   `localStorage.setItem` стоит прямо в теле `CourseCard`, то есть запись происходит при каждом render каждой карточки. Сразу после загрузки в localStorage оказывается id последней карточки, хотя никто ничего не выбирал, а любой повторный render записывает заново. Render должен только посчитать JSX из props и state и ничего не менять снаружи.

2. Кнопка «Выбрать»

   Теперь `CourseCard` только рисует название и кнопку и по клику вызывает `onSelect(course.id)`. Запись перенесена в обработчик `handleSelect` в `App`: там `localStorage.setItem`, лог `[write]` и `setSelectedId`. Строка `localStorage[selected-course]` показывает state, который читается из localStorage один раз при загрузке и обновляется по клику. У выбранной карточки появляется «(выбран)», а её кнопка становится неактивной.

   Проверка с пустым localStorage (ключ удалён через `localStorage.removeItem('selected-course')`): после загрузки `getItem` возвращает `null`. Три нажатия «Перерисовать» дают в консоли `[render] CourseCard ...` для всех карточек, но записи нет, значение всё ещё `null`. После «Выбрать» у «Серверный rendering» появляется один лог `[write] selected-course = next`, и в localStorage хранится `next`. Ещё два «Перерисовать» новых записей не дают. Для надёжности `Storage.prototype.setItem` в консоли оборачивался счётчиком: за всю проверку был ровно один вызов, и тот по клику.

3. Почему не Effect

   Если перенести запись в `useEffect` карточки, например `useEffect(() => localStorage.setItem('selected-course', course.id), [course.id])`, она всё равно не связана с кликом. Эффект запускается после того, как карточка отрисовалась, поэтому при загрузке все карточки сразу запишут свой id и останется последний, а в StrictMode эффект при монтировании выполнится ещё и дважды. То есть localStorage меняется до клика, и требование не выполняется. Выбор курса это действие пользователя, поэтому запись должна быть в обработчике клика, а не в render или эффекте.

Самопроверка: `npm run build` проходит без ошибок.
